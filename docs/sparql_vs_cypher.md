# SPARQL (ЛР 8) vs Cypher (ЛР 9) — Результат 5

> Порівняння виконується на **реальному підграфі** (47 вузлів, `synthetic = false`), бо SPARQL-сховище ЛР 8 містить лише їх. Для запитів `queries/cmp/c*.cypher` додано фільтр `synthetic: false`. Автоматичний збіг і час — `python run_compare.py` → `docs/compare_auto.md`.

## 1. П'ять питань

| Питання | SPARQL | Cypher | Очікуваний результат | Збіг |
|---|---|---|---|---|
| q1: активні ДТП і місце | `sparql/q1.rq` | `queries/cmp/c1.cypher` | INC_317/SEC_ST_07, INC_319/SEC_ST_11 | ☐ |
| q3: датчики за типом | `sparql/q3.rq` | `c3.cypher` | VideoCamera 2, InductiveLoop 1, RadarSensor 1 | ☐ |
| q4: маршрути → водії (OPTIONAL) | `sparql/q4.rq` | `c4.cypher` | 4 рядки; R_OPT_5 без водія | ☐ |
| q5: ДТП → затор → маршрут | `sparql/q5.rq` | `c5.cypher` | INC_317→R_OPT_3, INC_319→R_OPT_5 | ☐ |
| q6: досяжні перехрестя | `sparql/q6.rq` | `c6.cypher` | 6 впорядкованих пар (07, 12, 21) | ☐ |

Очікування взято зі збережених результатів ЛР 8 (`sparql/qN_res.csv`) та `docs/sparql_results.md`. Розбіжності, якщо виникнуть, ймовірні в q6: SPARQL використовує `(^:connectsTo/:connectsTo)+` (транзитивне замикання), Cypher — `*2..6` з обмеженням глибини; на 3 перехрестях результат однаковий.

Примітка: Cypher-версії довші, бо містять фільтри `synthetic: false`, потрібні лише для порівняння на спільному підграфі; без них q5 — це один рядок шаблону.

## 2. Порівняльна таблиця

| Критерій | SPARQL / RDF | Cypher / LPG |
|---|---|---|
| Читабельність | шаблони триплетів; потрібні PREFIX; шляхи `^p/p+` компактні, але специфічні | ASCII-art шаблон `(a)-[:R]->(b)` близький до діаграми; проста навігація по шляхах |
| Довжина (символів без PREFIX, q1/q3/q4/q5/q6) | q1: 139, q3: 124, q4: 137, q5: 64, q6: 99 | q1: 142, q3: 127, q4: 171, q5: 178, q6: 202 |
| Час виконання | вимірюється `run_compare.py` (Fuseki) | вимірюється `run_compare.py` (Neo4j); на 47–227 вузлах різниця в межах похибки |
| Зручність | стандарти W3C, вивід (RDFS/OWL), федеративні `SERVICE`, SHACL | зручні агрегації, `shortestPath`, GDS; властивості на зв'язках без реіфікації |
| Походження/метадані зв'язку | реіфікація, RDF-star або іменовані графи | властивості на зв'язку (`source`, `confidence`, `validFrom`) |
| Вивід/семантика | є (OWL/RDFS reasoner) | немає; підкласи — через додаткові мітки, що потрібно підтримувати вручну |
| Схема | відкрита, онтологія як дані | схемо-опційна; обмеження (unique) та індекси, без вбудованої семантики |
| Обмеження | вимагає IRI-дисципліни; складні шляхи з довжиною — дорогі | відсутня міжсистемна інтероперабельність; семантика залежить від домовленостей |

## 3. Висновок

LPG доцільний, коли головні задачі — обхід шляхів, аналіз впливу, алгоритми на графі та властивості зв'язків; RDF — коли потрібні стандарти, обмін між системами, вивід і зв'язування з Wikidata. У проєкті вони доповнюють одне одного: RDF — «джерело істини» онтології, Neo4j — аналітична проєкція.
